# 发布版本

1. 将 `CHANGELOG.md` 的 `[Unreleased]` 改为待发布的标签，例如 `[v0.3.9]`，保留实际变更内容，并在顶部新增空的 `[Unreleased]` 节供后续开发使用。
2. 本地检查发布说明：`python3 scripts/release_notes.py --tag v0.3.9`。缺少对应版本或说明为空时会失败。
3. 提交代码、更新日志，创建并推送相同的 `v*` 标签。标签中的文件是此次发布说明的来源，发布期间 main 分支的新改动不会混入。
4. `release.yml` 验证说明、运行测试、构建双架构安装包，然后用提取出的说明创建对应标签的 GitHub Release。重新运行发布任务会更新同一版本的说明和附件。

`release-notes.md` 同时包含在安装包中并作为 Release 附件保留。安装包也包含完整的 `CHANGELOG.md`。Web 检查更新仍通过 GitHub 最新版跳转获取版本号；发现更新后，通过 GitHub API 按该标签读取 Release 正文。因此，在 Release 页面修订说明后，下次打开升级弹窗就能看到修订内容。

未发布版本的说明不用于正式发布。历史版本没有说明时，Web 弹窗会明确提示该版本未提供发布说明；网络或 API 请求失败时提示重试，成功读取之前不能确认升级。
